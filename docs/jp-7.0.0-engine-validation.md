# JP 7.0.0 组卡引擎本地验证

2026-09-30，按用户要求读取 Toolbox 中指定日服账号的真实 suite，在本地副本模拟区域道具与门等级。原始本地验证未修改线上 suite；后续正式包验证见文末。

## 测试对象

- 修复版：`Team-Haruki/sekai-deck-recommend-cpp` 提交 `ab800540f82278da4aeb71784aeabe5a7cddccca`，包含 PR #9 无等级门修复和 PR #10 多团体区域道具适配。
- 对照版：本项目实际安装的 npm `haruki-sekai-deck-recommend-cpp@0.3.8`。
- 将修复提交及其固定的 yyjson 子模块源码导出到本地临时目录，以 Emscripten 5.0.7 / Release 编译 WASM；未修改 cpp 源码。
- 使用实际 CN05 日服 master JSON，文件集合与工具箱 `SEKAI_DATA_RECOMMEND_FETCH_MASTER_FILES` 一致。音乐 metas 使用本地已有数据，目标为 `power`，不会将其当作最新活动分数预测。
- suite 有 932 张持有卡，原始状态没有道具 56，5 个已有门均为 40 级。原始下载文件保持不变。

## 验证链路

实际调用本项目 `prepareDeckRecommendUserData()` → `prepareRecommendUserDataForWasm()` → npm wrapper → WASM，没有另写一套数据覆盖逻辑。验证新道具可被选项识别为双效果、最高 20 级；临时覆盖只插入一个用户道具，master 中的两行效果保持原样。

固定三类卡组：五个 OC 团体各一名角色、五名无支援团体的 VS、Leo/need 四名 OC 加对应支援 VS。各等级分别比较 `by_deck`、`force_on`、`force_off`；另外验证省略该选项时默认行为与 `by_deck` 一致。

这是本地 Bun 中运行真实 WASM 的集成验证，不是线上 deck-service 测试，也不是浏览器 UI 自动化测试。

| 五团 OC，大树 20 级 | 327,462 | 345,387 |

多团体满级案例补回 17,925 综合力。与理论倍率的微小取整差异按引擎对每张卡的三个基础属性分别取整检查。纯 VS 不错误启用条件加成；同团编成保留更大的全员匹配收益，不重复叠加多团体收益。

为了避免其他道具的全员加成掩盖判定错误，另将副本中的区域道具只保留大树：

| 卡组 | 自动判定 | 强制启用 | 强制关闭 |
| --- | ---: | ---: | ---: |

这同时证明带支援 VS 的卡组判定与全员加成取舍是两个独立步骤。

全卡池搜索使用全部 932 张持有卡、`dfs_ga`、综合力目标，并把搜索出的卡组固定后再次复算：

- 原始区域道具：418,144。
- 大树模拟 20 级：437,631。
- 两次结果均与固定卡组复算一致。它们是本次搜索结果，不宣称数学上的全局最优。

区域道具升级推荐也与完整复算一致：15→16 级对应商店 2116、收益 1,794；19→20 级对应商店 2120、收益 1,790；20 级不再生成后续升级。

最终 **53 项断言全部通过**。此次测试未发现修复源码与 Toolbox 数据覆盖/预处理之间的适配问题。

## 复现

仓库脚本：`scripts/verify-jp7-deck-engine.mjs`。需用 Bun 运行，因为它直接导入本项目 TypeScript 数据处理函数；它以私有目录中的 0.3.8 为反例基线，默认验证项目当前安装的 npm 包，也可通过第二个参数指定本地构建目录。

传入一个仓库之外的私有目录，布局如下：

```text
suite.json              # 真实 suite；不得提交
master/*.json           # 与前端使用集合一致的日服 master
music-metas.json
source-commit.txt       # 本地 WASM 对应提交
baseline/index.js       # 保留的 npm 0.3.8 对照包
baseline/package.json
baseline/sekai_deck_recommend.js
baseline/sekai_deck_recommend.wasm
```

```bash
bun scripts/verify-jp7-deck-engine.mjs /tmp/haruki-jp7-validation
```

脚本将汇总写到该目录的 `results.json`。实际样本、绑定身份和凭据均不进入仓库。此脚本需要与本次账号类似的角色覆盖及原始区域道具配置，前置检查会拒绝缺少所需卡牌的样本。

## 正式包回归

经用户授权发布后，Toolbox 9.4.0 已将精确依赖和锁文件更新至 npm `haruki-sekai-deck-recommend-cpp@0.4.1`。对 registry 实际安装的正式 WASM 重跑上述验证，53 项断言全部通过，主要综合力结果与本地修复版一致。工具箱 lint、类型检查、1,268 项单元测试、生产构建及 21 项 Playwright 测试均通过。

cpp 0.4.0 发布过程中，Windows MSVC 无法默认构造局部 `RowPick` 类型。提交 `2bccf46` 将其改为显式聚合初始化，未改变加成算法；本地 Python 绑定重新编译后，47 项测试全部通过。因为 npm 0.4.0 已发布，后续统一使用 0.4.1，不覆盖已有版本。

此次真实 suite 始终只用于本地验证，未回写线上数据。
